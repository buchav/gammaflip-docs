## What it returns

The levels of the `TOTAL` snapshot (all expirations combined) over a time
window, oldest first. One row per capture (`15m`), per hour (`1h`) or per session
(`close`). Use it to see how flip, regime and walls moved. For the per-strike
picture at one moment use [`/history/snapshot`](/api-reference/history-snapshot);
for bulk data use [`/history/files`](/api-reference/history-files).

Costs **1 request** against your [daily quota](/rate-limits). Read
[Historical data](/history) first for session dates, the close definition and
point-in-time semantics.

## Path parameters

<ParamField path="exchange" type="string" required>
  `bybit`, `deribit`, `okx`, `derive`, `combined` or `tradfi`. `all` and
  `combined` with a TradFi ticker resolve to `tradfi`. Venue subsets such as
  `deribit+derive` return `400 history_not_available`.
</ParamField>

<ParamField path="coin" type="string" required>
  Symbol, for example `BTC`, `QQQ`. Case-insensitive.
</ParamField>

## Query parameters

<ParamField query="start" type="string">
  ISO date or datetime, UTC. **Inclusive.** Default: `end` minus 30 days.
  Years 2020 to 2100 are accepted.
</ParamField>

<ParamField query="end" type="string">
  ISO date or datetime, UTC. **Exclusive.** Default: the end of the current
  15-minute capture slot, so the newest capture is included. `start` after `end`
  returns `400 invalid_param`.
</ParamField>

<ParamField query="granularity" type="string" default="close">
  `15m` (every capture), `1h` (the last capture of each UTC hour) or `close`
  (the last capture of each session date).

  | Granularity | Maximum window |
  |-------------|----------------|
  | `15m` | 31 days |
  | `1h` | 180 days |
  | `close` | unlimited |

  A longer window returns `400 range_too_large` with `max_window_days`.
</ParamField>

<ParamField query="cursor" type="string">
  The opaque `meta.next_cursor` of the previous page. Pass the same `exchange`,
  `coin`, `end` and `granularity` as before. `start` is replaced by the cursor, so
  pages never overlap.
</ParamField>

## Pagination

A response has at most **5,000 rows**. When there is more, `meta.next_cursor` is
set (otherwise it is `null`); send it back as `?cursor=` to get the next page.
With the window limits above, `15m` and `1h` requests normally fit in one page;
paging matters for long `close` ranges.

## Response

<ResponseField name="data" type="array">
  One object per row. `type` is `close` only for the last capture of a completed
  session, otherwise `intraday`. `oi_date` is the session whose open interest the
  row used (see [Historical data](/history#point-in-time-no-look-ahead)).

  The fields are `schema_version`, `timestamp_utc`, `session_date`, `type`,
  `exchange`, `symbol`, `oi_date`, then the levels fields: `spot`, `flip`,
  `flip_count`, `regime`, `net_gex`, `abs_gex`, `call_gex`, `put_gex`,
  `call_oi_total`, `put_oi_total`, `p1_strike` ... `a2_gex`, `s_price`, `s_gex`,
  `v_price`, `v_gex`, `max_pain`, `atm_iv`. All are defined in the
  [data dictionary](/data-dictionary). Rows are `TOTAL`, so there is no
  `expiration` or `dte` field and `max_pain` is always `null`. Missing values are
  `null`.
</ResponseField>

<ResponseField name="meta" type="object">
  `exchange` and `coin` as requested, `symbol`, `exchange_resolved`, `market`,
  `units`, `docs_url`, `granularity`, `start` and `end` (as applied, ISO 8601
  UTC `Z`), `next_cursor`, and your `rate_limit`.
</ResponseField>

## Errors

<ResponseField name="400 history_not_available" type="error">
  Venue subset. The body includes `valid_exchanges`.
</ResponseField>

<ResponseField name="400 range_too_large" type="error">
  The window is longer than the granularity allows. The body includes
  `max_window_days`.
</ResponseField>

<ResponseField name="400 invalid_param" type="error">
  Unparseable `start`, `end` or `cursor`, `start` after `end`, a year outside
  2020 to 2100, or an unknown `granularity` (the body includes `valid_values`).
</ResponseField>

<ResponseField name="400 invalid_exchange / invalid_pair" type="error">
  Unknown venue, or a venue that does not match the coin's market.
</ResponseField>

<ResponseField name="403 market_not_in_plan" type="error">
  Your plan does not include this coin's market.
</ResponseField>

An empty window is not an error: `data` is `[]`. Check
[`/history/coverage`](/api-reference/history-coverage) for where history starts.

<RequestExample>

```bash cURL
curl "https://api.gammaflip.io/api/v1/history/levels/tradfi/QQQ?start=2026-09-01&end=2026-10-01&granularity=close" \
  -H "X-API-Key: gex_sk_your_key_here"
```

```python Python
import requests
import pandas as pd

H = {"X-API-Key": "gex_sk_your_key_here"}
url = "https://api.gammaflip.io/api/v1/history/levels/tradfi/QQQ"
params = {"start": "2026-09-01", "end": "2026-10-01", "granularity": "close"}

rows = []
while True:
    body = requests.get(url, headers=H, params=params).json()
    rows += body["data"]
    cursor = body["meta"]["next_cursor"]
    if not cursor:
        break
    params["cursor"] = cursor

df = pd.DataFrame(rows)
print(df[["session_date", "spot", "flip", "regime", "net_gex"]])
```
